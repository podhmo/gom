## 各レーンの要点

### A — named func 型

`type CancelFunc func()` 形の named func 型を `Go.FuncN` として読む
（method-less のみ）。登録された `pkg.F` という handle と
signature-boundary の `Go.FuncN` ビューを両立させ、`unify` は
FuncN 側と突き合わせるときだけ handle を `FuncNOfNamed` で展開
する設計（別 handle 同士は混同しない）。`lower.Env` に
`FuncNOfNamed` フックを追加 — stdlib が `Types` を `typeOracle`
で包んで任意インターフェースを落とすため、第一級フックが必要
だった。`goimport.Loader` は `FuncNOfNamed`（ロック）と
`funcNOfNamed`（無ロック・member ロード中の呼び出し用）に分離
しないと自己デッドロックする。

### B — `Array.make` の init 引数

ADT/Option 要素のゼロ値生成が安全でないため、`Array.make n init`
と初期値を必須化。stdlib/list・testdata/spec は機械移行。

### C — 予約語と E0106

spec §1.8 に 22 語の予約語一覧と E0106（reserved word used as a
name）を明文化。`nameKeyword`（= keyword かつ非宣言開始語）で
束縛位置をゲートし、宣言開始語は従来の E0101 回復を維持。
レビューで見つかった抜け道 2 件を追加で閉じた:

- ctor パターンの引数（`Some send`）— `atPatArgStart` が keyword を
  除外して E0101 化していた。`as`/`in`/`if` を除く nameKeyword を
  受理（3 語はパターンの正規終端）
- select の `send <- ch` / `default <- ch` — send/default 腕の
  分岐が先に発火していた。`<-` 続きは予約名 receive 腕として
  `parseReservedRecvArm` へ回す

### D — 共有前提 Go 型

`Ptr sync.WaitGroup`・`Ptr errgroup.Group` 等が W0702/W0701 を
鳴らすノイズに対し、プロンプト選択肢 (a) の閉じた builtin
allowlist を採用。`sync` 同期プリミティブ・`sync/atomic` 語型・
`errgroup.Group` を `types.NamedRef` で列挙し、`Ptr X` 形のみ免除
（Ref/Array ペイロードや record フィールドは外側コンストラクタが
書き込み可能なので警告を維持）。spec §10 に記載。

### E — type alias 構文

`AliasBody` は parser に到達経路がなく死んだノード。
`type A = Int` は単一バリアント sum として静かに受理される
（UIdent 衝突）。採用には新しい綴りが要るため defer を推薦 —
decision `2026-11-21-type-alias-syntax`、gaps 台帳に登録済み。
