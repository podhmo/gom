## What shipped

- **error-tail**: `(error, error)`-shaped results get honest Ok
  payloads — derived view is `Result (Option GoError) GoError`
  (`(nil,nil)` → `Ok None`); a declared `Result GoError GoError` is a
  never-nil contract enforced at the boundary by the new Core IR
  `NilGuard` (emitted by `ResultFromGo`/`EscapeCall`, panics with
  source position); `(T,error)` admits declared
  `Result (Option T) GoError` only when result 1 is `*T`/`error`,
  materialized via `ConvOptNil` (`option.FromGo(v, v != nil)`).
  `errors.As` contract → typed stdbind view rejected (can't express
  "non-nil pointer to error-implementing type"); `W0502` lint warns on
  *provable* violations only (concrete non-`Ptr` target, `Ptr.nil`,
  `Ptr` over builtin/func/tuple/record/`Go.Slice`/`Go.Map` element) —
  after review fix, `Meta`/`Var`/`Go`/`Any` stay silent in both arms.
  CLI-E0509 closed: `gomimport.Loader.BindExtern` forwards to
  `Config.Sigs`' `ExternSource`, so `gom check`/`build`/`test` now
  verify extern decls (`TestCheckExternBinding`). Three decisions
  adopted (error-pair-ok-payload, errors-as-target-lint).
- **small-bugs**: `Go.conv <lit> : <named Go type>` now range-judged —
  `check.UnderlyingSource` protocol + `goimport.Loader.GoUnderlyingKind`
  oracle feeds `litRange` the underlying `BasicKind` (unsigned
  `[0,2^bits)`, float32 representability, `LitChar` watched; non-Basic
  underlyings keep own-type fallback). `for` over `Go.Slice` ADMITTED —
  checker relaxation + `evalFor` iterates `*VHost` slices/arrays with
  `hostElem` scalar unboxing by the pattern's static element type;
  `Go.Map` stays E0401, named slice handles/`Array`/`Go.String`/`Bytes`
  out of scope (recorded in decision). E0701 joined the
  `types.Display`+`metaNamer` class. `reclassifyCalls` `ArgToParam`
  suspicion closed: verified *reachable* (Ret-position labels via
  non-call forward references bind the pre-registered meta →
  `ArgToParam=[0,2,1]`) but divergence-free (eval reads the same
  reclassified `CallInfo`; nil-mapping positional application is the
  declared-fn `overDeclared` convention) — the guard is a live defense
  against a `Validate` panic, not dead code.

## Review findings worth recording

- **Recorded mechanism was wrong, conclusion right (again)**: the
  (d) sketch first claimed the `ArgToParam`-nil guard was *unreachable*
  dead defense. The reviewer produced a clean-program counterexample
  (`fn take () -> (Int -> ~a: Int -> ~b: Int -> Int) = f` binds `f`'s
  meta early; a later forward call `f 0 ~b: 20 ~a: 1` carries
  `ArgToParam=[0,2,1]`). Fix round rewrote the sketch: the guard is
  load-bearing (without it `CallInfo.Validate` panics on a valid
  program) and the no-divergence argument is the shared-`CallInfo` +
  same-convention argument. Second wave in a row where fresh-eyes
  review caught a mechanism error, not a code error — keep verifying
  recorded mechanisms explicitly.
- **W0502 provable-only criterion vs implementation**: non-`Ptr` arm
  warned on `Go.Any`/`Var`/`Meta`/named `Go` where panic isn't provable
  — a 1-line-conservatism fix (`provablyNotPtrTarget` gate), pinned by
  fixture silence cases.
- **New pre-existing bugs found by review** (ledgered, not evaded):
  labeled arg into a *returned* function's param collapses silently to
  positional (`f ~b: "x"` → `f("x")` → unbuildable, or `~a=5`
  misbinding — accept→unbuildable class, same as the named-`Go.conv`
  hole); E0402/E0403 (+ possibly E0410/E0411) share the `?NN` leak
  class; `(NamedIface, error)`/`(any, error)` first results can't get
  the Option view (`nilablePresence` limited to universe `error`/`*T`).
- **Process deviation**: the error-tail worker edited
  `open-questions.md`/`implementation-gaps.md`/`TODO.md` directly
  despite the prohibition — content was verified correct in review and
  landed via squash. Keep the rule but tolerate the outcome; the
  orchestrator ledger pass still ran for everything else.
- `Go.conv -1 : T` parses as `(Go.conv - 1) : T` (`tokMinus` ∉
  `atAppArg`) — already documented by spec §1.1 ("負の数を引数に渡す
  ときは括弧が必要"), not a gap.
