## lane 1 — cons 位置の自己再帰を buffer loop 化する lower 特殊化

- PR: https://github.com/podhmo/gom/pull/46
- 採択（podhmo）: (a) match-cons 再帰形を検出して buffer loop を emit。
- `internal/lower/consrec.go`: `match { .. } :: rest -> f(head, rest)` 形の
  自己再帰（uses==1・tail 位置の cons 適用）を検出し、`core.TailCall.Prepend`
  + `core.Func.ConsLoop` フラグで codegen に buffer loop を指示 — 生成コードは
  Array 的 buffer への prepend 蓄積後 `to_list` 相当で結果を組み立てる。
- 保守的な境界: head が可変値の読みを持つ場合（`Var{Sym.IsGo}`、mutable
  recv の `GoFuncRef`/`FieldGet`）は特殊化しない — rewrite は head の読みを
  unwind 後→loop 継続前へ移すため、時刻に敏感な head だけ残す（`stableHead`）。
- review 2 findings 修正: mutable head timing（`stableHead` 導入、619053d）、
  adopted decision の sketch 検証レポート欠落（bdeee20 で追加）。
- decision: `docs/decisions/2026-11-18-cons-recursion-spec.md`。

## lane 2 — `gom run` サブコマンド

- PR: https://github.com/podhmo/gom/pull/47
- 採択（podhmo）: (a) `gom run` 新設（compile→temp dir→exec）。
- `gom run [-format F] FILE|DIR... [-- ARGS]`: gom build → temp dir へ
  `go build -o`（`build.RunGoRunBin`）→ 子プロセス exec。
  `go run` ラッパーではなく直接 exec — `go run` は子の exit code を
  "exit status 1" に潰すため。
- argv・stdin/stdout/stderr・exit code を passthrough; signal kill は
  `syscall.WaitStatus` から 128+signal を返す（`os.Exit(-1)` の 255 化け回避）。
- link error は `NewGoPosIndex` に `srcs` を渡して `.gom` span へ fold
  （`gom build -go` と同じ経路。回帰テスト `TestRunBuildErrorFoldsSpan`）。
- 成功時は対象プログラムが stdout を所有、失敗時のみ spec-12 の message
  stream を出す非対称を spec/design に明記。
- review 3 findings 修正（上記 fold・signal・台帳残件 3件）。
- decision: `docs/decisions/2026-11-18-gom-run.md`。

## lane 3 — `concat` の O(k) スタック解消

- PR: https://github.com/podhmo/gom/pull/48
- `stdlib/list` の `fn concat` を `@extern` 宣言に切り替え、
  `stdlib/list/impl.go` の `Concat[A]` が総長 prealloc + `append(...xs...)`
  の 1 回コピーで実装 — O(1) スタック・O(n)・1 alloc（k=512 で ~72×）。
- 従来の `rev_append` 連鎖は再帰深度 O(k) で lane1 の特殊化も乗らない形。
- review finding 修正: supersession decision
  `docs/decisions/2026-11-18-concat-extern.md` 追加（cons-buffer decision の
  「concat は .gom のまま」部分を Supersedes）。
