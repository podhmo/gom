## pitfalls

- 診断 fixture の `-update` は JSON を意味的に再エンコードすると、key 順や `->` / `|>` の escaping で無関係な差分を量産する。compiler の wire order を保ったまま、explicit empty assertions だけを最小挿入する必要がある
- 空配列 assertion は「フィールドがない」と「空であることを要求する」の意味が違う。fixture 更新で落ちると、negative fixture が意図した strictness を検証していないことがある
- record recovery の二次診断抑制は、quiet meta を局所的に持ち回る形でないと、独立した constraint mismatch まで消える。共有 `wantT` でも no-match 側の独立診断は残す fixture が要る
- 字下げヒューリスティックは AST expression span ではなく行の最初の token 列を見る。grouping parens は AST node を作らないため、見た目と構文木の開始列がずれる
- `docs/error-codes.md` は生成物。本文を直すときは `internal/diag/codes.go` を直して `go generate ./internal/diag` する
- E0407 候補 label は local record だけでなく import `.gomi` の declaration span まで必要。`.gomi` 側に span を出さないと text label を落とす設計になる
- E0201 `namespace: "member"` は通常の module member だけではない。`Go.Map` / `Go.Slice` の operation table miss は constructor fallback 経路でも member 診断なので、typo 候補の対象から外すと実用例を取りこぼす
