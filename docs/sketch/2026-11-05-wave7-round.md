## Work and review protocol

Same protocol as Waves 4–6: one implementation agent per lane, each in
its own managed worktree; a fresh read-only reviewer per completed
branch; findings returned to the implementer (or applied by the
orchestrator when they were doc/nit-level and the implementer had
already exited); squash merge after review. Implementers do not edit
TODO.md / open-questions.md / implementation-gaps.md /
TODO-archive.md — they report proposed ledger updates; the
orchestrator applies them. Concurrency was capped at 2 implementation
lanes following the Wave 6 rate-limit incident.

## What shipped

- **divergence**: numeric arithmetic is per-operation machine
  semantics — literals are nearest binary64, each operator executes
  once in the machine type, constant folding is not language meaning.
  `lower` emits literal-only divergent ops (`Float` arith/compare,
  Int `+ - * /`) through a temporary so Go cannot fold them as untyped
  constants; this also fixed the `MaxInt64 + 1` go-build failure.
  Wrong-variant `.f` is an assertion: eval reports E9003, generated Go
  panics via the existing type assertion (spec §3.2/§8.6).
- **interop-ops**: `Ptr` module (rt-backed): `get`/`set` (Go-nil
  panic), `is_nil`, `new`, `make`, `nil`, `to_option`. `Go.Map`
  member table: `make`/`get` (Option)/`set`/`delete`/`length`/
  `to_list`; non-comparable keys are E0508, nil-map behavior is Go's.
  W0501 warns when a Unit-returning Go call receives a *copied*
  List/materialized Go.Slice argument where in-place mutation is a
  no-op; verbatim slice paths stay silent.
- **gomtest**: `gom test` runs `.gomi` conformance (E0601/E0603) and
  withholds generated artifacts + test execution for failing groups;
  Go panic stacks are re-rendered to `.gom` positions via
  `GoPosIndex.RenderStack` (`-q` suppresses the raw stack); `gom test
  -- FLAGS` forwards verbatim after the always-first `-json`.
- **slice-ops**: `Go.conv` between `Go.Slice T` and `List T` copies in
  both directions (checker `convKind` consults `goConvKindOf`;
  `list.FromSlice`/`.ToSlice()` runtime paths). `Go.Slice` gained
  read-only member ops `length`/`get`/`slice` (shared view, Go
  panic)/`fold`/`to_list` via the same ctor-table mechanism as
  `Go.Map`. `SliceToList` returns the slice — the generated
  conversion performs the sole snapshot copy.
- **lower-residuals**: `@tailrec` R4 (`CheckTailRecMutual`) now runs
  the mutual-recursion reference graph over the package unit —
  sibling-file cycles `a.f → b.g → a.f` and `let`-mediated cycles
  report E0904, matching the earlier `CheckInitCycles` unit-ification.
  Identical nested-`go` W0702 warnings dedupe per span. Guarded and
  unguarded `EscapeCall`/`EscapeResult` spans all use the step
  operand. Unbound metas in key E0401 messages display as
  per-diagnostic `?1, ?2, ...` via `types.Display`/`metaNamer`.
- **int32-eval**: integer ops are width-aware via the static operand
  type at the operation node — `VInt` keeps a canonical invariant
  (Int32-typed values are stored sign-extended), `evalPrim`/
  `evalUnary`/`litValue` normalize and wrap. `MinInt32 / -1`,
  `MinInt32 % -1`, `-MinInt32` all match Go's int32 answers; the
  `ParseUint` fallback also lets `-9223372036854775808` materialize
  as MinInt64 (previously an internal error). Host-injected VInts
  must arrive pre-normalized (doc.go contract).

## Residual boundaries (recorded, not evaded)

- `Go.conv` between `Go.Slice T ↔ List U` with representation-equal
  but different element types (`Go.Slice Int64 → List Int`) still
  falls through to a `list.List[T](xs)` cast pun — same class of
  aliasing hole as the fixed same-element case, now a soundness bug in
  TODO.
- W0501 misses an inline `Go.conv e : Go.Slice T` argument (the
  copy-materializing form is `Ascribe{Slice:false}`); let-bound
  versions are intentionally silent.
- `checkInterfaces` groups test files by `filepath.Dir` without
  `filepath.Clean` — `pkg/../pkg/a.gom` splits one physical directory
  into two groups and can dodge missing-member conformance. Bug
  recorded.
- `for x in gs` over `Go.Slice` is rejected by the checker although
  Core IR can represent `ForList` over it — open design question.
- E0904 `through`/`path` can leak hidden `tmpN_xxxx` VarDecl names
  (R4 doesn't reuse E0907's `nodeName`/`DiagName`); E0407/E0409/
  E0801 still display raw meta mint IDs (the `?n` renumbering is
  E0401-only). Both recorded as diagnostic-quality tasks.
- Int-literal range check is absent in check — `let n : Int32 =
  3000000000` typechecks but the emitted Go cannot build. Problem doc:
  [2026-11-05-int-literal-range-check.md](../problems/2026-11-05-int-literal-range-check.md)
  (found during int32-eval verification).
