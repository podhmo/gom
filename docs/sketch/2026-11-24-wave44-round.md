## 学び（pitfalls）

- **positional-slice residual は非 prefix fill を誤ラベルする**:
  `params[len(args):]` は「残り」を位置で近似するだけで、label
  先行の fill では実際の未供給 slot とずれる。正の residual は
  `applyResidual`（宣言カリー分割を保つ）が必要 — ただし fill set
  が静的に決まるときだけ（spread/`..`/Hole/未解決ラベルは不可）
- **リテラル正規化のタイミングは2段**: checkPat の Norm はその
  arm 判定時の want で採られるが、後の arm body が scrutinee meta
  を named 幅（Float/Go float32）に bind しうる — checkMatch 末尾で
  全 LitPat を settle 済み want で re-judge する。pattern 側には
  Go-underlying oracle がないので re-judge は check 内が正しい位置
- **eval に float32 値はない**: VFloat は f64 オンリー — compiled
  の f32 比較と eval の f64 比較で `16777217.0` が分岐する真の差異
  だが修正は eval の値表現拡張を要し lane 超過（escalate、wave45
  候補）
- **`@method` の `Int`→`int` 境界は残る**: `int64` を要求する
  interface（`io.Seeker.Seek`）には emit が合わない — types.Equal
  は通るが生成コードが Go コンパイルで不一致（台帳登録済み、
  wave45 候補）
- **labeled residual は位置 want を取れない**: `pair ~y:` の残余は
  `~x: Name -> String` で、`Name -> String` とはそもそも非互換 —
  label 付き部分適用は lane 対象外であることを fixture で確認
