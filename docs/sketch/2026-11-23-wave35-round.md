## 学び

- emit 台帳は「請求」と「emit されるか」を分けないと腐る — sibling の
  `@test` helper は `UnitScope.Decls` にモード無関係で残るため、
  `gom build`（test half 非 emit）では請求から外す必要があった
  （`core.File.Tests` を新設）
- `testName` の dedup は「どの名前が取られたか」も警告対象 —
  base だけでなく suffix 先の占有人を見ないと `TestX2` 奪取が
  無言になる
- spec は決定時に同期し、実装先行のずれは implementation-gaps に
  台帳する — 調査 lane の decision 採択時は「実装 lane で spec」
  と書くより、spec を直して台帳に載せるほうが AGENTS.md の
  規則に忠実（#152 レビューで指摘）

## 実装で発見したずれ

- verbatim 二重請求（`Foo_Bar`/`FooBar`・`Some_Opt`/`SomeOpt`）は
  W0601 で検出するが**壊れた Go を emit し続ける** — 負け側を
  error にするか suffix 退避するか未決。fuzz 経路で検出され、
  knownBugs 2 件 + TODO タスクとして台帳化済み
