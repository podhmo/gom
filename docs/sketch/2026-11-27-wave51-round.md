- lane F の `gom info` は read-only inspection と draft generation の 2 面を持つ。inventory を tool-first にしても、compiler-registered member と module context 依存は静的な案内が要る

- lane E の labeled callback probe では、positional lambda が最終 conformance で合法でも、推論時に label 付き文脈を捨てると record update が型付かなかった

## pitfall 一般化

- **成功 conformance を失敗と型不等から区別する**: conformance は型を変えずに通るとは限らない。回復診断を suppress するなら、失敗そのものを checker が trace する
- **coverage evidence は存在と意味を分ける**: meta-test で固定できるのは evidence の所在まで。assertion の polarity や分類理由は表と review の責任として明示する
- **tool inventory は解決条件ごと書く**: コマンドへ寄せる瘦身でも、同名 path 優先・module context・compiler-registered surface などツールだけでは見えない条件は guide に残る
- **module 合成は go.mod だけでは終わらない**: checksum、workspace、GOFLAGS、replace path quoting、cache invalidation、既存 project への additive edit までが利用者可視の contract である
- **accept に使える label を inference contract にしない**: label は最終 conformance の借り物であって、speculative inference variable に残すものではない。推論には label-erased view、判定には従来の labeled rule、という境界にする
