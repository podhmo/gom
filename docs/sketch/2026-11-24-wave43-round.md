## 学び（pitfalls）

- **literal→meta bind の順序が pin を無力化する**: 共有メタ
  `?b` を持つ部分適用 `pair "x"`（`?b` が result に出ない形）
  では、供給リテラルの conform が先に `?b := String` を bind
  してしまい want 側の `Name` に materialize できない。
  数値リテラルは pendingLit 式に bind を遅延するが、スカラー
  リテラルは concrete 型で即座に bind する — 真の修正は bind
  の遅延で、pin の param 拡大ではない（#215 escalate、lane F
  で台帳登録済み）
- **`Mat` ascribe は「値」であり eval no-op**: literal
  materialization は let-restriction の値規則を破らないよう
  `isValue` が透過し、eval は内側をそのまま返す。結果として
  1-field record の値は裸スカラ — field access・record
  pattern・display の三面で unwrap 規則を揃える必要がある
  （Float-backed は VInt→VFloat の coerce が要る）
- **generic 関数内の ShowPlan は package-level helper にできない**:
  `List a` のように宣言 Var を含む operand は helper mint を
  止めて %v recipe に degrade させる — 生成 Go で未定義型
  パラメータを参照しないための `hasTypeVar` ゲート
- **fixture の syntax error は陽性ケースを無効化する**:
  `ok_interp_composite.gom` が record literal を `:` で書いて
  いて E0101 で parse 停止 — expected.json がそのエラーを
  期待していても補間の本筋は検査されていなかった（#216
  レビュー指摘）
