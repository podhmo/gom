## 各レーンの要点

### A — 単一フィールド record → defined type

`type UserId = {value: Int}` は `type UserId int64` を emit する
ようになった — Gom の newtype 綴りとしての意味を持つ。
`.value` は `int64(u)`、`{value = v}` / `with` は `UserId(v)`、
`gomEq`/`gomShow` も `F(v)` 経由。判定は `check.DefinedField`
（ローカル）と `TypeOracle.DefinedField`（インポート）に集約し、
codegen は core の `FieldGet{Unwrap}`/`Conv{ConvNamed}` を読む
だけ。`type X a = {f: a}`（フィールドが裸の型パラメータ）は
Go が `type X[A any] A` を拒否するので struct フォールバック —
stdlib/cmp の `Eq`/`Ord` は defined type 化済み。
[decision](../decisions/2026-11-21-record-single-field-defined-type.md)、
golden `record_one_field.gom`。

### B — record pun

`{x, y}` = `{x = x, y = y}` を literal・`with` 更新・pattern に
導入。`{x}` 単独はブロック式のままなので 1 フィールドの pun は
`{x,}` と末尾 `,` が要る（spec 8 章）。fixture `ok_record_pun`。

### C — spread `f ~..opts`

record 値の各フィールドをラベル名で引数へ対応づける呼び出し。
record 以外は E0418、対応する `~name` が無いフィールドは
E0406、ラベルの重複は E0405。spread 値は単純式 1 つ
（複合式は `~..(e)` と括る）、record は一度だけ評価される。
レビューで重要な制約が見つかった: **spread 元は named record
が必須** — フィールド解決が宣言済み record 型の索引を見るため
匿名 `{to = 1}` リテラルは E0401。
[decision](../decisions/2026-11-21-record-spread-arg.md)。

### D — Go iface impl 設計

設計調査のみ（podhmo 指定）: `@method` 属性 + 規約命名、
.gomi は fn リスト、`InterfaceMethods` oracle の形で decision
draft `2026-11-21-go-iface-impl.md` まで。実装は採否待ち。

### E — `type alias X = T`

wave28 lane E の defer 推薦を Supersede して採用
（[decision](../decisions/2026-11-21-type-alias-adopt.md)）。
`alias` は `type` と UIdent の間だけで効く文脈依存キーワード
（`let alias = …` は無傷）。`type X = …` は常に新しい型、
`type alias X = T` が透明な別名、の一本化。lint ガードは偽陽性
（正当な単一バリアント）を避けられず見送り。

Devin Review で潰した下流バグ 4 件:

- 前方参照: `registerTypeDecls` が alias を pass 1 で kindAlias
  化していなかった → `aliasBod` を保持し `applyTypeCtor` で
  lazy 解決（`resolveAlias` の aliasIn 循環ガードがそのまま効く）
- インポート経由の arity: 修飾名 `p.Ints` が tyBySym を見ず
  展開後シグネチャの Con から arity を取っていた → tyBySym 経由で
  `ctorOfInfo`
- E0415 bypass: 上の修正で `sigOf`/`shadowedSigDiag`（builtin
  shadowing 検査）を素通りした → `sigOf` を先に呼ぶ順序に戻した
- iface drafter が `type X = T` で出していた → `AliasType` なら
  `type alias` を書く
