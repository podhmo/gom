## 発見メモ

- 無名 record literal は「期待型がない」場合でも field set が一意なら推論できる。必要なのは backward inference 位置または field set が曖昧・未対応の位置だけという区別が review で補強された
- 未注釈 `let` にも checker は expected meta を渡す。quiet recovery の設計では「meta がないときだけ quiet meta を作る」のではなく、既存 meta 自体を quiet にする必要がある
- 調査 lane で見送った候補を open-questions へ登録するのは closeout の役目。lane PR では検証レポートへ残すに留める
- 継続行 hint の対象は match/if arm だけではなく、関数本体 block を含む mid-block statement 全般である
- `checker` には lint 専用の独立 state がほとんどなく、lint は typed AST・type table・diagnostic list を読む形だった。state grouping でも無理に `lintState` は作らない方が自然だった

## pitfall 一般化

- **推奨形の文脈を一意推論と逆推論で分ける**: 「期待型がない」と「型が一意に決まらない」を混ぜると、ユーザーへ過剰な注釈を勧める
- **recovery artifact は bind せず quiet にする**: `Unit` へ bind すると後続使用で artifact mismatch が増える。root error 確定後の recovery は診断ノイズを出さない設計にする
- **誤パース診断は suppression より先に導線を付ける**: 連鎖を畳む診断は false positive で独立エラーを隠しうる。まず最初のエラーに修正方向を出す方が安全である
- **大規模 refactor は embedded state で参照形を保つ**: field access を全面書き換えずに grouping できると、file split と意味変更を分けたまま review できる
