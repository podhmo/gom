## pitfall 一般化

- **表示は「値の表現」ではなく「生成側が選べる recipe」に合わせる**: evaluator は scalar payload として保持していても、compiled が opaque/nominal として扱う位置では括弧・width・符号を静的型から決める。逆に型パラメータが残る composite は typed renderer を mint できないので、再帰せず全体を runtime fallback に倒すのが compiled 側の境界
- **小さな表示修正は算術意味論まで掘り返す**: named Go scalar の表示ずれを追うと uint32/uint64 の wrap・符号表示・record 内 quote まで出た。表示の compare test は leaf だけでなく record/list/tuple/variant に入れた形で必要
- **test helper を runtime 本体へ置くと依存が production に漏れる**: go-cmp のような test-only 依存は `rt/testutil` に分けないと、test を使わない利用者の module metadata まで壊す
- **snapshot はファイル名・cwd・環境変数の境界が本体**: 機能自体より、test binary の cwd capture、update env の明示、atomic write、UTF-8 byte limit、dedup されない source test 名のほうが review で効いた
- **spec fixture は diagnostics が空でも規則の形を写す**: 差分 compare があるだけでは足りず、ユーザー可視ルールは `testdata/spec` 側にも nested 形を残す
