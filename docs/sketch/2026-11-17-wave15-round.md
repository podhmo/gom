## 逸脱・メモ

- 単一セッション実行でレビュー往復がレーン内に収まった（Devin Review の auto-fix/triage 経路）。レビュー findings はすべて「具体失敗例を名指ししてから修正」の手順を維持 — #22 の 1 件のみ false positive。
- **「実 build context のモック/ステージングはそれ自体が挙動バグの温床」**: lane-4 の temp-dir staged `go build` は機能したが、レビュー 2 ラウンドで 6 findings — すべてステージングが現実と食い違う箇所だった:
  1. モジュールルート配下に temp dir を作ると `sub/internal` の可視性規則で sibling package の build が失敗 → パッケージ dir 配下（`.gomlsp-*`）に変更
  2. 「sibling に `.go` があれば Go package として stage する」判定が `.gom` を含む dir（Gom package + 手書き helper）を取り込み、`.gomi` に未定義のシンボルを偽エラー化 → `.gom`/`.gomi` 存在時は Gom package として skip に戻す（自分の前回修正で悪化させた回帰）
  3. `//go:embed` の資産が stage にコピーされず sibling build が失敗 → sibling `.go` の embed pattern を辿って資産も stage
  4. `//go:embed ../x` が staging 中にワークスペース外のファイルを上書きし得る → `.`/`..` セグメントを持つ pattern を拒否（compiler でも invalid なので整合）
  5. go.mod 先頭行の `module<TAB>path`（tab 区切り）を module directive として認識できず module 解決が失敗 → `strings.Fields` token 化で受理
  6. 上記に伴い stagedNames/位置付けの整合を修正
  教訓: 「X が存在するか」の判定を足すときは「それが *自分が思っている種類の* X か」の対称面を必ず検査する（`.go` 存在 ≠ Go package）。また adversarial probe は入力だけでなく *環境構造*（モジュール配置・embed・混在 dir）を変化させる必要がある — 単体の入力 variant では 6 件のうちほとんどが釣れなかった。
- lane-4 の Eglot 検証について podhmo 裁定: プロトコル面（wire format）を変えない lane では実 Emacs/Eglot は不要 — in-process JSON-RPC テストで publishDiagnostics の payload を確認すれば十分。一旦 blueprint に入れた `emacs-nox` は削除済み。今後の LSP 系レーンはこの方針で検証する。
- PR チェーン: #23→#22、#24→#23、#25→#24 と lane 順に base を積む chained PR 構成（stack ではない）。マージは下から順に。
