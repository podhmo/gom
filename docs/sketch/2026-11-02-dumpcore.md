# B-8: treedump for Core IR + phase-dump fixtures

`treedump.DumpCore(*core.File) string` renders the Core IR in the same
S-expression format as `DumpSyntax` / `DumpResolved` / `DumpTyped`
(docs/decisions/2026-11-02-treedump-format.md). Alongside it,
`gomtest.RunDumpTests` adds a third suite kind: generator-registered
phase dumps, kept as `.dump` sidecars under `testdata/dump/`. This
sketch records what is covered, how the pieces fit, and what a future
`gom dump -phase=X` or lower/check dump would plug into.

## Coverage

Every Core node family is rendered (internal/treedump/core.go):

- file/imports — `(file@sp pkg@pkgsp ...)`, `(import@sp "path" sym%N [:go])`
- decls — `(type ...)`, `(let ...)` for `VarDecl`, `(fn ...)`,
  `(test@sp "name"@namesp (fn ...))`
- type bodies — `(sum (variant Ctor%N (field@sp :T name -> sym%N :iI)))`,
  `(record (field@sp :T x -> x%N :iI))`, `(alias@sp :T)`,
  `(abstract@sp)`; `(tparams a b)` for type parameters
- functions — `(fn@sp name%N :sig [residual=R] [:tailloop]
  (tparams ...) (params (param@sp :T sym%N)) (body ...))`. `residual=`
  appears only when `Func.ResidualType()` differs from `Sig.Ret`
  (arity splitting); `:tailloop` marks `TailLoop` self-recursive fns
- bodies — `(body lets... (tail E))`; let binders inline as
  `(let@sp :T name%N@bindsp E)` so the common case stays one line.
  Nil binders render as `(let@sp ? E)`; discard binders as
  `(let@sp :T _@bindsp E)`
- atoms — `var`, `lit` (with lit kind and quoted value), `funcref`
  (arity + targs), `ctorref`, `gofuncref` (arity/results/recv),
  `fieldget` (field sym or bare `:iN` for tuple indices), `builtin`
- calls — `calldirect`, `ctorapp`, `callfunc`, `tailcall` (`to=fn`),
  `callgo` (`arity=N results=<one|err|err-only|ok|pair> [variadic]
  [spread] [recv ...]`), `callbuiltin`
- escape/conv — `escaperesult`/`escapecall` (`to=<fn name or
  sym>`), `resultfromgo`, `optionfromgo`, `tuplefromgo`,
  `conv` (`num|named|box-any|iface|slice-to-go|slice-from-go`)
- composites — `list` (`(rest E)` tail), `tuple`, `record`, `update`,
  `closure` (wrapping an anonymous `(fn ...)`), `if`, `binary`,
  `unary`
- concurrency — `select` with `recv`/`send`/`default` clauses, `for`
  (`list|chan` kind), `go` (`core.Spawn` renders under the `go`
  head, matching the syntax/typed dumps)
- decision trees — `match` wraps `dswitch` (`type|tag|value|list`
  kind), `case` (`ctortest|littest|listtest` + `bind` binders + body),
  `default`, `guard`, `leaf`, `panic`
- `(syms ...)` trailer interning every `*resolve.Symbol` reached —
  modules, types, ctors, fields, funcs, vars, go funcs/methods,
  builtins — as `%N` in first-appearance order

Nil markers follow the established convention: `:?` for nil types,
`?%` for nil symbols, `(?)` for nil nodes, `SwitchKind(?)` / bare `?`
where a malformed enum/field would otherwise vanish.

## gomtest dump suite

```go
gomtest.RunDumpTests(t, "testdata/dump", map[string]gomtest.DumpFunc{
    "core/sample": func() (string, error) { return treedump.DumpCore(coreSample()), nil },
    // future: "check/x": func() string { return treedump.DumpTyped(...) },
})
```

- The map key is the case name; `a/b` maps to `<dir>/a/b.dump`.
  Nested names nest subtests, so all Core dumps group under `core/`.
- The suite validates names (no abs paths, `..`, backslashes, `.dump`
  suffix, dup after clean) — a bad generator name is a harness bug,
  so it errors immediately rather than writing outside the suite.
- `.dump` files on disk with no registered generator are orphan
  errors — deleting a generator deletes its fixture, same contract
  as golden cases.
- `.case.json` manifests sit next to the `.dump` (not `.gom`): the
  manifest name is `<dir>/<case>.case.json`; `{"skip": "reason"}`
  skips just like spec/golden cases.
- `-update` writes/changes fixtures the same way; diffs and missing
  fixtures go through the same normalize/diff helpers as golden
  (CRLF + trailing-newline normalized before compare).

The design differs from spec/golden in one respect: generators are Go
functions, not `.gom` pipelines. That keeps the suite usable before
a phase has a parser-facing driver — Core IR can't be produced from
source yet (lower isn't wired end-to-end), so the fixture constructs
`core.File` trees directly. When `gom dump -phase=core` exists, a
`.gom`-input variant can layer on top; the sidecar/manifest/update
machinery stays.

## Determinism

- Symbol interning is single-pass, first-appearance order — no map
  iteration anywhere in the walk; `%N` numbers are stable across runs.
- `TestDumpCoreDeterminism` dumps `coreSample()` 10× and requires
  byte-identical output; the `TestRunDumpTests*` tests exercise the
  suite end-to-end.
- `Func.Sig`/`ResidualType` render via `types.String` (deterministic;
  no pointer addresses). Function targets for `to=` resolve by name
  or symbol ref — never raw pointers.
- Ordering note: `core.File` decl order is source order (not sorted),
  which is what a phase dump should show — reordering happens in
  earlier phases, not in the dump.

## Verification

```text
$ ~/sdk/go1.27.1/bin/gofmt -l .    # (empty)
$ ~/go/bin/go1.27.1 vet ./...      # clean
$ ~/go/bin/go1.27.1 test ./... -count=1   # all ok
$ make check                        # incl. check-sumtype, experiments — all ok
```

`TestDumpCore` goldens every family; `TestDumpCoreNilMarkers` pins
the `?`-rendering of a deliberately malformed file;
`TestCoreDumpSuite` exercises the gomtest runner against
`testdata/dump/core/sample.dump`.

## TODO / future work

- `check`/`pattern`/`lower` dump generators once those phases produce
  inspectable IR — register `"check/..."` names in the same suite.
- `gom dump -phase=X` CLI flag reusing DumpCore / future DumpX.
- A `.gom`-input dump runner (`RunDumpTests` variant taking
  `func(gomtest.File) string`) once a phase can run end-to-end from
  source.
- Consider rendering `types.Type` for `(fn ... :( -> Unit))` —
  currently faithful `types.String` output reads `:( -> Unit)`; fine
  as-is but a `()` special case would read better if it annoys.
