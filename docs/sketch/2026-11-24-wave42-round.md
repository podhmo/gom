## 学び（pitfalls）

- **package 宣言は merge するが import は file-local**: 複数
  ファイルの package は decls が一つに畳まれるので、shared
  loader の汚染を潰すだけでは足りない — sibling file の import
  が同じ package の別ファイルの record literal 判定に漏れる。
  ファイル単位の可視集合（`fileVis`）で foreign 候補を絞る
- **「import 無しファイル」も可視集合に seed する**:
  `importRootsByFile` が import 持ちファイルしかキーを作らない
  と、import 無しファイルでは ambient（unscoped）の宣言まで
  落ちる。decl を持つ全ファイルに空 roots を seed して
  `TypeDeclsFor(nil)` が unscoped テーブルを返すようにする
  （lane A レビュー指摘）
- **defined type 系の規則は `definedUnderlying` の peel に集約する**:
  `~` 制約・`Go.conv`・literal 範囲判定・literal 代入可能性と、
  「Go では defined type」という判定が全て同じ peel で書ける。
  新しい規則を足すときは「Go の defined type ならどうなるか」
  に還元すると spec も実装も一貫する
- **リテラル型が宣言型に解けたら emit でも materialize する**:
  型検査で受理するだけでは `x := 0` が Go の default `int` を
  束縛して型を失う — lower で `Conv`（`UserId(0)`）を敷く。
  named Go 型のリテラルと同じ仕組みで統一できた
