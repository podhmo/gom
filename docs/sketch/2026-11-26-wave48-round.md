## wave の経過

小さな correctness bug から始め、cache・emit・interface metadata と toolchain 内部の再現性へ進み、後半は stdlib surface と spec 整合に進んだ。lane D が最も大きく、directive attachment だけでなく alias 正規化・fmt・cache fingerprint まで同じ author metadata の寿命として揃える必要があった。lane E は実装より命名が焦点になり、`string` は自然に見えるが生成 Go の predeclared type を利用側 alias が覆すため `str` に退けた。

## 発見メモ

- lane A では表示されない `Unit` payload でも、補間 operand が生成 Go で使われないと束縛が unused になる
- lane B では cache commit 時の再読みは race を避けられず、compile 時に観測した bytes/stat を manifest に残す必要がある
- lane C では file identity・directory identity・output collision を同じ canonicalization に寄せられない。symlink された共有 file は両 package の member、directory は canonical、output は physical collision
- lane D では signature canonicalization で import alias を潰すとき、置換結果を再スキャンすると import path 自体を壊す。lexical literal を避けた単一 pass が必要だった
- lane E では stdlib 短名は Gom 側の見た目だけでなく、生成 Go の package alias が predeclared 型名を覆すかまで見る必要がある
- lane F では spec の正確さが「許される操作」だけでなく、abstract でも許される wildcard match のような非操作まで分かれる

## pitfall 一般化

- **identity は用途ごとに分ける**: lexical file identity、canonical directory identity、physical output identity は同じ symlink の前で違う答えを返す。安易に共通 helper へ寄せると片方の意味を壊す
- **canonical form の変換は冪等性ではなく入力言語の lexical boundaryで考える**: import path のような生成 key を文字列置換で作ると、次の置換が key の内側を書き換える。string literal / struct tag を通る単一 pass scanner が必要
- **stdlib 命名は host language の namespace と衝突しないか試す**: Gom 側で衝突しなくても、生成 Go の import alias が predeclared type を覆すと型位置が壊れる
- **CLI filesystem 振る舞いと language diagnostic fixture を混ぜない**: `testdata/spec` は言語診断の harness で、module graph と出力ファイルの性質は CLI/end-to-end test の責務
- **docs mismatch 掃除でも negative space を書く**: abstract 型でできないことだけ書くと wildcard match まで禁止に読める。表現を見ない操作が残ることも spec の意味
