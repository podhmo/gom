## 発見メモ

- OSA は adjacent transposition を 1 として数えるが unrestricted Damerau-Levenshtein ではない。`ca` → `abc` は OSA recurrence では 3 で、negative fixture の期待をこれに合わせた
- import `.gomi` の declaration span を text rendering へ出すには、compile 後に disk へ読み直すだけでは不足する。compile 時に loader が見た bytes を保持しないと、削除・変更された dependency で span を解決できない
- absolute span file を `NewDirResolver` が suite dir に join すると二重 path になる。dependency source は resolver が absolute path を扱える必要がある
- explicit-empty `notes`/`labels` だけでは negative fixture の structured data absence を固定できない。wave56 では harness-only `data_absent` を足した
- hidden Go member は table に入るが使うと E0501 になる。candidate source は「存在する」だけでなく「候補として意味がある」ことを見る必要がある
- 調査 lane PR は前 lane 未 merge の間 chained diff になるため、review は前 lane の実装指摘を再検出する。round では lane 固有の結論と inherited implementation follow-up を分ける必要があった

## pitfall 一般化

- **typo candidate は spelling 正しさだけでなく usability で絞る**: hidden member やその位置で使えない kind を勧めると、修正しても別エラーになる。candidate source は closed であることに加え、visibility/kind/context を見る
- **dependency source は compile-time snapshot として扱う**: 診断 rendering は compile 後なので、disk re-read は race と missing file に弱い。必要な interface bytesは load 時点で capture し、成功経路では寿命を明示する
- **portable fixture は update path まで設計する**: 手で `span.file` を省いても `-update` が絶対パスを書き戻すなら fixture は壊れる。省略 assertion の preserve/normalize を harness 側で考える
- **調査 lane の review は chained diff を前提に読む**: base に前 lane を含む以上、review finding が investigation scope に入らなくても台帳へ落とす。closeout に実装修正を混ぜない
- **security sanitizationは renderer-wide で考える**: 1 診断だけ escape すると他経路が残る。source snippet の terminal control 文字は renderer の責任として扱う
