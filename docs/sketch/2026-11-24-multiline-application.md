# 検証: 複数行カリー適用 — NL-2 維持の確認

wave44 lane G、[decision](../decisions/2026-11-24-multiline-application.md) の検証レポート。

## 手順

`testdata/gocall` モジュール配下に一時 fixture を置き `gom check` を実行
（検証後に fixture は除去）。

## 結果

| 形 | 結果 |
| --- | --- |
| `List.fold\n  (fn acc x -> acc + x)\n  0\n  [1,2,3]`（ブロック内） | E0407（`List.fold` 単体がジェネリック部分適用）。続く各行は別のブロック項目として扱われ、末尾の `[1,2,3]` はブロックの**結果**として型検査される — 期待型が `Unit` なら E0401、`List Int` なら受理。末尾以外の分離行は E0402/E0407 |
| 同上（ファイルスコープの `let`） | 続く行が宣言でないため E0101 |
| `xs |> List.fold (fn acc x -> acc + x) 0` | ok |
| `(List.fold\n  (fn acc x -> acc + x)\n  0\n  [1,2,3])` | ok（NL-1: 括弧内の改行は空白） |

## 文法変更案の破壊量

`(` を line-start に加える案は `f ()\n()` — Unit ブロックの標準
終端 — を `f () ()` に読み替える。`testdata/` 配下で
`^\s*()$` を数えると 110 行あり、そのうち直前が `{` で終わる
1 行（NL-2 が既に改行を殺す `each_word`）と既存エラー fixture 内の
37 行（既に失敗するため「新たに拒否」には当たらず、expected.json の
診断内容更新が要るだけ）を除いた 72 行が現行で通る慣用形の破壊対象
— 慣用形を大量に拒否することになるため却下（`[` もブロック値としてのリストリテラルを壊す）。
