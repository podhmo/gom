## pitfalls

- expected type による lookahead は「完全な unification replay」と「構造だけの pattern match」のどちらでも足りない。speculative unification で共有/curried-tail 規則を使いつつ、外部 meta へは直接 bind せず、構造的に有益な解だけ replay する境界が必要だった。
- replay 用の open meta を quiet にすると mismatch まで消える。E0407 だけを抑える `silent` と、診断 cascade も抑える `quiet` の使い分けが重要。
- shared open argument（`Pair a a`）は concrete でなくても equality 制約を運ぶ。wholly open だから落とす、ではなく共有されているかを見る必要がある。
- DMMF probe は compiler unit test とは別の価値がある。型名前置 literal / stdlib helper / 短絡の修正が実用形で組み合わさるかを小さい runtime test で確認できた。
- 1 フィールド record は JSON object ではなく defined scalar として emit される。DTO guide のような docs でも「record + struct tag」だけでは足りず、表現ルールまで確認が必要。
