- DMMF probe は compiler unit test とは別の価値がある。型名前置 literal / stdlib helper / 短絡の修正が実用形で組み合わさるかを小さい runtime test で確認できた

- closeout PR を早めに作ると、下位 lane の review 修正で compiler diff が混ざって見える。最終的な cascading rebase 後は #269 が round/prompts の 2 ファイルだけになった

## pitfall 一般化

- **speculative type inference は外側を汚染してはいけない**: expected type による lookahead は「完全な unification replay」と「構造だけの pattern match」のどちらでも足りない。共有/curried-tail 規則を使う trial を clone 上で行い、外部 meta へは直接 bind せず、構造的に有益な解だけ replay する境界が必要だった
- **trial の診断抑制は伝播させない**: replay 用の open meta を quiet/silent にすると、必要な mismatch や E0407 まで後続 conformance へ伝播して消える。未共有の wholly open solution は reification 前に落とし、共有されている open solution だけ通常の診断を持つ fresh meta で replay する必要があった
- **open でも equality 制約は情報になる**: shared open argument（`Pair a a`）は concrete でなくても equality 制約を運ぶ。一方が bare meta、もう一方が nested な構造の中にだけ現れる共有も数えないと、後続フィールドの曖昧 record を early enough に disambiguate できない
- **docs の boundary 例は表現ルールまで確かめる**: record 型があることと JSON object として emit されることは別。境界 guide では型だけでなく生成表現まで見る
