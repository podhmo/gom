## 学び（pitfalls）

- **import 宣言のフィールドの名前解決は import 先スコープ**:
  caller が `type List` のような builtin shadow を宣言していても、
  foreign 宣言のフィールドに非修飾で書かれた `List` は import 先の
  builtin を指す。型チェッカが宣言のフィールドを畳むときは宣言の
  スコープも一緒に畳む（`cmpWalk` は `foreign` フラグで実現 —
  foreign 宣言の型引数は lazy 置換で caller スコープに戻る）
- **shared loader は宣言情報を累積する**: spec suite の 1 つの
  `gomimport.Loader` を subtest 間で使い回すと
  `registerForeignTypes` が「これまでに読んだ全 .gomi」を畳み込み、
  import した fixture の record フィールド名が後続 fixture の
  literal 持ち主判定を汚染する（ledger 登録済み・fixture 側は
  ユニーク名で回避）
- **再帰型を畳むとき instantiation を落とさない**: `Tree a` の
  `l: Tree a` を畳むとき raw の arg（`Var a`）をそのまま再束縛すると
  外側の `a → Int` が消える — expand 入口で outer subst を arg に
  適用してから比較・置換する
- **Go generic の signature 名 shadow は E0415 が別経路で捕捉する**:
  `type List` shadow 下では `[]E` を取る Go generic（`goiface.Count`）
  は boundary の builtin `List` 綴りで先に落ちる — comparable 判定の
  正例ピンには `Lookup[K comparable, V]` のような map キー経路が要る
