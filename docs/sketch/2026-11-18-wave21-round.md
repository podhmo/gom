## lane 1 — CtorApp/CtorRef の TypeArgs を validator で検査

- PR: https://github.com/podhmo/gom/pull/57
- 採択（podhmo・prompts 時点）: (a) optional-but-authoritative —
  `TypeArgs` は省略可だが、書かれているなら validator が
  constructor signature の arity と照合する。
- core validator が CtorApp/CtorRef の `TypeArgs` を構造検査する
  経路を追加（下流フェーズが信用してよいのは「書かれた値は正しい
  形」まで）。
- review で TypeArgs 検査の立ち位置を decision に明文化:
  `docs/decisions/2026-11-18-ctor-typeargs-authoritative.md`。
- (b) `TypeArgs` を必須化し canonical にする案は future work —
  open-questions に記録。

## lane 2 — stdlib 分割 + Result.to_option / Option.to_list

- PR: https://github.com/podhmo/gom/pull/58
- 採択（podhmo・prompts 時点）: 層変換メンバーの案とおり —
  メンバーは下層モジュールの面、実装は上層パッケージの forward
  関数（`option.ResultToOption` / `list.OptionToList`）。
- stdlib を `list`/`option`/`result` の3パッケージに分割済みの
  土台の上に、`builtinMember.pkg` 上書きで層をまたいだ配置を実装
  （`Array.to_list` → `list.ArrayFreeze` と同型）。
- `List.to_option` は案Bで棄却済み（decision に記録）。
- decision: `docs/decisions/2026-11-18-stdlib-conv-placement.md`。
- spec fixture: `testdata/spec/ok_stdlib_conv.gom`。

## lane 3 — 独立 dir グループの並列コンパイル

- PR: https://github.com/podhmo/gom/pull/59
- design §5-6 残件を実装: `compileInputs` を dep グラフ由来の Kahn
  層でスケジュールし、層内で GOMAXPROCS ワーカーが並列に `compile`。
- 同期: `goimport.Loader` を go.mod + go.work 単位で共有・全公開
  メソッドに mutex（cfg.Dir が Go コンテキストのみなのでプール可）。
  `gomimport.Loader` は per-dir のまま（cfg.Dir が EntryPath/
  自己 import 経路の identity なため）。
- buildCache: 全メソッド mutex + pooled Go dep の merge（複数 dir
  で共用された池の dep を commit が拾えるよう goPoolKey 単位で
  蓄積）。
- 依存先 `.gomi` の再生成が依存側の読み取りより先に終わるのは層
  構造が保証（dep ファイルは先行層で完了）。
- review findings 修正: go.work 下の池分離（goPoolKey+workFile）、
  相対 path の Rel 失敗（Abs 化）、循環 fallback の二重スケジュール
  （1 dir 1 層 + break）。
- decision: `docs/decisions/2026-11-18-parallel-dir-compile.md`、
  検証 `docs/sketch/2026-11-18-parallel-compile-verify.md`。
- `gom build -o` は単一入力専用のまま。`gom info` の .gomi 出力は
  全コンパイル後にまとめて書く（dep の .gomi は読む順序を守る）。

## lane 4 — List 由来の読み取り専用 View 型

- PR: https://github.com/podhmo/gom/pull/60
- problems/2026-11-04-shared-slice-view-type の保留分を List 側に
  解く: 組み込み型 `View a`（repr `list.View[A]`、素 `[]A` の
  named 型）。List が不変なのでバッキング共有は安全 —
  部分取り出し・添字アクセスが O(1)。
- 面: `List.view`・`List.slice`、View モジュール（length/get/
  slice/fold/to_list — すべて読み取り専用）。`for` の反復対象に
  追加（checkFor + core validator ForList）。
- メンバーはすべてコンパイラ登録（`builtinMember` + `pkg` 上書き
  → `stdlib/list` 手書き関数）。`.gomi` 宣言にしない理由:
  @extern の生成名 `View` が `type View[A]` と衝突する。
  `list.gomi` のコメントに存在を記録。
- Go 由来の共有 View は足さない（Go.Slice の読み取り専用面で
  足りる — decision 2026-11-04-goconv-list-slice-copies どおり）。
- decision: `docs/decisions/2026-11-18-list-view.md`、
  spec fixture `ok_stdlib_view`・golden `stdlib_view`。
