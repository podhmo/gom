## 学び

- **directive の「位置」は cache 鍵・formatter・codegen の3箇所で
  一貫している必要がある**: `//gom:embed` は comment run の隣接性で
  意味が変わるが、canonHash はテキストのみ・formatter は空行を
  正規化する — 同じ invariant を参照する全経路で接続性情報を
  保存しないと「見た目だけの変更」が意味を変える
- **blank import を alias 表に混入させない**: 空欄 alias `_` を
  `imports[path]` に入れると named import との同 path 共存と
  `imp()` の返り値両方を壊す。別 map で管理するのが自然
- **パッケージ DAG が API 形を決める**: `list` が `cmp` を
  参照できないため `sort` は `Ord` dict 形ではなく comparator
  形の `sort_by` になった。依存順が設計の制約として先に効く
- **三項スライスは Go 側テストでしか見えない**: `xs[:n]` の
  capacity 残留は Gom の値検査では観測不能 — `boundary_test.go`
  のような Go 側 assertion が必要

- **型名の判別は「位置」で分岐できる**: `///` が attr と decl の
  間にあるかは `AttrSp`（`@` トークンの span）でしか判定できない
  — comment の絶対位置ではなく「attr より後」の相対位置が意味を持つ
