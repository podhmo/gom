# P4-3 ファイル内テストと `gom test` — 実装・検証メモ

## 実装の構成

- `internal/lower`: `Env.Tests` で `test` 宣言と `@test` 定義を Core に残す
  （build では従来どおり落とす）。`test "name" { ... }` は core.TestDecl
- `internal/codegen`: decl を 2 系統の generator に振り分け。TestDecl と
  `@test` decl は `_test.go` 側、それ以外は本体側。`assert` は
  `rt.Assert(t, cond)`、`assert_eq` は `rt.AssertEq(t, eq, showActual,
  showExpected)` に下げる。`show` は比較対象の型ごとに自動生成
  （core/lower/codegen の ShowDecl 系）。失敗時は両方の値を文字列化して
  表示する（spec 11.4）
- `internal/build/gotest.go`: `go test -json` を走らせイベントを
  diag.TestResult に変換。Action pass/fail/skip、Elapsed、出力、
  ソース位置（//line で .gom に戻る）
- `internal/diag`: `kind:"test"` メッセージをフル形状で schema 化
  （name/func/ok/skipped/elapsed/位置/失敗時の値）。summary.Tests で
  run/failed/skipped を集計
- `cmd/gom/test.go`: `gom test [-format F] [FILE|DIR ...]`。Tests モードで
  コンパイル → .go/_test.go を書き出し → パッケージごとに `go test -json`
  → メッセージストリームへ翻訳。`go test` 自体の失敗（モジュール無し等）
  は E0001 diagnostic + exit 1

## 検証

- E2E: `@test fn double` + `test "double works"` を `gom test` → `m.go` /
  `m_test.go` 生成、`_test.go` 側に helper と TestDoubleWorks、
  `go test` パス（/tmp/p43e2e で実 module 確認）
- `go test -json` の非 Gom テストも name をそのまま拾う（spec 12 表の
  `func` は -run セレクタとして使える）
- TestTestsModeEmitsTestFile が両半分の振り分けを pin

## 残課題

- `go test` が走るのは生成ファイルを置いたディレクトリ — ユーザーの
  go.mod が必要（無ければ E0001）。`gom test` 自身が module を用意するかは
  未決
- 失敗時の値表示は文字列化のみ。`assert_eq` の差分表示（diff形式）は
  していない
- テストの並列実行（`go test -parallel` 相当）・`-run` フィルタは未実装

メッセージ wire 形・`go test` のパッケージ粒度・`assert_eq` 表示の細部は
[decision](../decisions/2026-11-03-gom-test-message-stream.md) と、より
詳しい検証レポート [gom-test-verification](2026-11-03-gom-test-verification.md)
を参照。
