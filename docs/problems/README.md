# problems: 懸念事項

実装中に気づいた懸念（設計上の矛盾、将来困りそうな点、spec と実装の食い違いなど）を 1 件 1 ファイルで置く。名前は `YYYY-MM-DD-<slug>.md` で、日付は作成日。内容や状態を更新してもファイル名は変えない（並列の worktree で衝突しないよう連番は使わない）。

- 書くこと: 状況、なぜ問題か、関連する spec / design / decision / TODO の ID、考えられる対応
- 明らかなバグは TODO.md の `## Bugs` に、決めるべき論点は [open-questions.md](../open-questions.md) に書く。ここは「まだどちらとも言えない懸念」の置き場所
- 解消したら先頭に `- 状態: 解消（<理由やリンク>）` を書く。ファイルは消さない
