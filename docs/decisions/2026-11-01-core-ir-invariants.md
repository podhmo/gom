# Core IR の不変条件

- 状態: 採用
- 日付: 2026-11-01

## 背景

言語の意味の判断を Go コード生成器に持ち越すと、複雑さが `codegen` に集中する。

## 決定

Core IR の時点で次を確定させ、`codegen` は機械的な変換だけを行う。

1. 評価順序（ANF。ラベル付き引数の並べ替え、`_` プレースホルダ、`select` の腕の式を含む）
2. 関数の arity と呼び出し規約（飽和呼び出し、部分適用、未知の関数値への適用、Go 関数の呼び出し）
3. Go 相互運用の変換（`Result` への変換、数値変換、ボックス化、スライスのコピー、interface への代入）
4. match の決定木（ADT の不正値に対する panic の分岐を含む）
5. 脱出ノード（`try` と `|?>` が抜ける関数境界）
6. 型の具体化と必要なラッパー
7. ソースの由来

あわせて、型付き AST の適用ノードは呼び出し情報（呼び出し対象、型引数、引数の数、未適用の引数、呼び出し規約）を構造化して持つ。名前解決済み AST を独立した段階として置く。診断はコンパイラ内部のデータ型を正とする。
