# 数値演算は演算ごとの機械演算（定数畳み込みは意味に含めない）

- 状態: 採用（実装・検証した — [検証](../sketch/2026-11-05-numeric-arithmetic-per-operation.md)）
- 日付: 2026-11-05

## 決定

`Int` / `Int32` / `Int64` / `Float` の算術演算は、式の中の各演算子ごとに
機械型で 1 回ずつ評価する。

- `Float` のリテラルは書かれた値に最も近い `float64`（IEEE 754
  binary64）を表し、各演算子は被演算子の `float64` に IEEE 演算を適用した
  結果を返す。`869.32 * 38.29` は `float64(869.32) * float64(38.29)` と
  同じ値 `33286.262800000004` になる
- `Int` 系の演算は 64 ビット（Int32 は 32 ビット）の 2 の補数
  wrap-around で行い、オーバーフローはエラーではなく値が回る
- 定数畳み込みは言語の意味に含めない。`let a = 869.32` のあとの
  `a * 38.29` と、リテラルのままの `869.32 * 38.29` は同じ値を返す。
  値がリテラルか変数かで結果が変わることはない

生成コードはこの意味を守るため、被演算子がすべて数値リテラルの数値演算
（`Float` は `+ - * / < <= > >= == !=`、`Int` 系は `+ - * /`）では、
オペランドを変数経由で実体化して Go の定数式判定を回避する。変数は Go の
定数式にならないので、生成コードは実行時に演算ごとの機械演算を行う。

比較・等価（`Float` の `< <= > >= == !=`）も同じ扱いにする — 異なる
リテラルが同じ `float64` に丸められると、正確な値どうしの比較と
`float64` どうしの比較がずれる（`0.1 + 0.2 == 0.3` は false）。

## 背景

評価器は各リテラルを `float64` にしてから演算する（上記の意味そのもの）
のに対し、生成コードはリテラル式をそのまま出力していた。Go はリテラル
だけからなる式を untyped 定数として任意精度で畳み、境界で 1 回だけ丸める
ため、`869.32 * 38.29` が `33286.2628` になり最後の ulp でずれる
（[problem](../problems/2026-11-02-float-const-fold-arithmetic.md)、
V-3 の eval-vs-compiled 差分テストで発見、knownDivergences 登録済み）。

選択肢は 3 つあった:

1. **演算ごとの機械演算（eval に揃える）** — 生成コードがオペランドを
   非定数化する。式指向言語として自然: リテラルを `let` で名前を付けても
   結果が変わらない。OCaml / Rust / Go（実行時）と同じ読み
2. **正確に畳んでから 1 回丸める（生成 Go に揃える）** — eval が定数
   部分木を任意精度で畳む必要がある。`let a = 869.32` で `a * 38.29`
   の値が変わり、リファクタリングで観察可能な差が生まれる
3. 第三の案（hybrid 等）は検討する実益がない

(1) を採る。Int 系も同じ規則にする: `9223372036854775807 + 1` のような
定数式は Go が "constant overflows int64" で拒否し、生成コードが
ビルドできないという別のずれ（こちらは clean 実行さえできない契約違反）
を同じ機構で防げる。`Int` は check の constFold と同じく `let` 束縛の
変数を定数とみなさないので、リテラル式だけが対象になる。

非対象:

- 単項 `-` — 符号反転は丸めを伴わず、畳んだ値と実行時の値が一致する
- `Bool` / `String` / `Char` の演算 — 畳み込みと実行時評価が常に一致する
- `Int` 系の `< <= > >= == !=` — 整数比較は正確で、丸めで値が
  マージされることがない（リテラルは型の範囲内と check が保証する）

## 実装

lower の `binaryExpr` / `eqExpr` で、fold の対象になる演算子かつ被演算子
型が対象の数値型のとき、両オペランドが `core.Lit` なら左オペランドを
一時変数に束縛する（右だけでも良いが左を選ぶ — 1 つの束縛で式全体が
非定数になり、右リテラルは変数の型 `float64` 等に 1 回丸められるので
eval のリテラル解釈と一致する）。ascription は lower で透過なので
`core.Lit` の検査は check の constFold の定数式判定と同じ面を覆う。
