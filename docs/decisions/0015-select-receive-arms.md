# 0015 `select` の受信腕はチャネルごとに 1 つの `case`

- 状態: 採用
- 日付: 2026-11-01
- Supersedes: 0009 のうち、受信腕のパターンと同一チャネルの腕をまとめる規則

## 背景

0009 では `Some job <- jobs` と `None <- jobs` のように受信腕にパターンを書き、同じチャネルへの腕をまとめて 1 つの Go の `case` にする予定だった。しかし「同じチャネル」の判定が構文的になる（`x <- f()` と `y <- f()` は別のチャネルかもしれない）。また、Go の `select` の「通信できるものを選ぶ」段階と、受信値による分岐が混ざり、評価の回数も Go とずれる恐れがある。

## 決定

- 受信腕の左辺は変数か `_` だけ。型は `Option a`
- 値による分岐は腕の本体で `match` を使って書く
- 各腕は Go の `select` の `case` に 1 対 1 で対応する
- チャネル式と送信値は、`select` に入った時点でソース順に 1 回ずつ評価する（Go と同じ）

## 影響

- 閉じたチャネルの処理漏れは、通常の `match` の網羅性検査で見つかる。`select` 専用の網羅性検査（旧 E0305）は不要になった
- コード生成が単純になる
