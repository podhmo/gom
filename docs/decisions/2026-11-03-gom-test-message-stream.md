# `gom test` message stream and `go test` execution granularity

- 状態: 採用
- 日付: 2026-11-03

## Context

[inline-tests](2026-11-01-inline-tests.md) decided that `gom test` emits a
`_test.go` and translates `go test -json` into `kind: "test"` messages, and
[test-file-emission-layout](2026-11-03-test-file-emission-layout.md) decided
which declarations land in each generated file. Neither pinned down the
wire shape of the `test` object, what happens to package-level aggregates,
or how much of a package's tests `gom test` runs. P4-3 had to decide those.

## Decision

- The `test` object carries `name` (the `test "name"` name; for tests Gom
  did not generate, the Go function name), `func` (the generated Go test
  function — usable directly as a `go test -run` selector), `ok`,
  `elapsed` (seconds as reported by `go test`), `output` (only when the
  test emitted output — on failure this includes both `assert_eq` values
  and the `.gom` position recovered through `//line`), `skipped` (only
  when true; a skip counts as `ok: true`), and `span` (the name position
  of the `test` declaration; absent for tests Gom did not generate).
- `gom test` summaries carry `"tests": {"run","failed","skipped"}`; other
  commands omit `tests` entirely. `summary.ok` is true only when there are
  no error diagnostics *and* no failed tests.
- `go test` runs at package granularity: once per directory holding an
  input file, running the whole test binary. Tests from sibling `.gom`
  files and handwritten `_test.go` files run too and are reported as
  `test` objects without `span` (`name == func`). We do not pass `-run` —
  same-package tests can interfere with each other, and the test binary
  must build as a whole anyway.
- `go test` build output/failures and invocation failures become E0001
  diagnostics with `"source": "go"`; `file:line:col:` positions resolve
  back to `.gom` through the generated `//line` directives. A stale
  generated `_test.go` for a `.gom` that no longer has tests is removed —
  only files carrying the `// Code generated by gom.` marker, never
  handwritten ones.
- `assert_eq` renders both operands through a compiler-generated
  `func gomShowN(v T) string` per operand type (`core.ShowDecl`, emitted
  into `_test.go`). The format matches the evaluator's comparison
  rendering (`internal/eval.Value.String`): `(1, 2)`, `[1, 2]`,
  `{ name = "n" }`, `Ctor ~name: v`, `Ok 42`; nested operands get parens
  only for records, variants, errors, and function values (the evaluator's
  `writeOperand` rule). Go-originated values use `fmt` `%v` per spec 11.
  Minting has its own 128-entry budget mirroring equality; exhaustion
  degrades to `%v` silently — a worse failure message, never a wrong
  verdict.

## Consequences

- spec.md section 12 documents the `test` object, `summary.tests`, and the
  package-granularity rule; design.md 4.8 describes the emission,
  `codegen.Output.Tests` mapping, and `rt.AssertEq` display-string args.
- Added `diag.TestResult`/`Report.Tests`/`TestCounts`,
  `internal/build/gotest.go` event folding, `codegen.Output.Tests`, and
  the `ShowDecl` pipeline (lower → core → codegen).
