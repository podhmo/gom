# `try` の脱出先は最も内側の関数

- 状態: 採用
- 日付: 2026-11-01

## 背景

ラムダの中で `try` を使ったときの脱出先が決まっていなかった。仕様の例にも、`Result` を返さないラムダの中で `try` を使う誤りがあった。

## 決定

- `try` は、それを囲む最も内側の関数（`fn` 定義またはラムダ）から抜ける。`test` ブロックも関数境界とする
- その関数の戻り値型は `Result _ e` で、`e` は `try` した値のエラー型と一致しなければならない
- `go { ... }` は関数境界ではない

## 影響

- Core IR では、`try` と `|?>` を「どの関数境界から抜けるか」を明示した脱出ノードにする（[core-ir-invariants](2026-11-01-core-ir-invariants.md)）
