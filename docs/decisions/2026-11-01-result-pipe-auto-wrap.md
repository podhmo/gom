# `|?>` と `%w` による自動ラップ

- 状態: 採用
- 日付: 2026-11-01

## 背景

`strconv` をはじめ、Go の標準ライブラリの多くは `(T, error)` を返す。毎回 `match` や `try` で受けていては Go のパッケージを素直に使えない。また Go の慣習では、エラーに文脈を付けて `fmt.Errorf("...: %w", err)` で包む。

## 決定

- 演算子 `|?>`（F# の `Result.bind` 相当）を追加する。`|>` とは別の演算子にする
- エラー型が `GoError` のとき、失敗したステップで `fmt.Errorf("<ステップ名>: %w", err)` を自動で付ける
- ステップ名は右辺の関数名（パッケージ名付き）。ラムダならソース位置
- 包むのはエラーが起きたステップでの 1 回だけ
- エラー型が `GoError` 以外なら包まない

## 保留

- ラップの文言を設定可能にする（future work）。`strconv` のようにエラーがもともと関数名を含むパッケージでは、既定の規則だと関数名が二重に付く
- `try` でも同じ自動ラップをするかは未決

## 影響

- 生成コードは `if err != nil { return ... }` の早期リターンに展開し、中間の `Result` 値は作らない

## 追記（明確化）

- ステップ名は、右辺の式の先頭にある名前をソースに書かれたとおりに使う。`let f = parse_toml` のあと `|?> f` なら `f`。関数値の由来は追跡しない
- 自動ラップは `Error()` の文字列を変えるので、公開される振る舞いの一部として扱う
