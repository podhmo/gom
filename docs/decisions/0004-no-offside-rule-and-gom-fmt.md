# 0004 オフサイドルールを持たず、出力が一意な `gom fmt` を持つ

- 状態: 採用
- 日付: 2026-11-01

## 背景

並置の適用では改行の扱いを決める必要がある。一度は「継続行だけインデントで判定する」限定的な規則を入れたが、インデントに意味を持たせるより、フォーマッタで一意に整形できるほうが望ましいと判断した。

## 決定

- インデントは意味を持たない。改行の解釈はトークンだけで決める（Go の自動セミコロン挿入に近い規則）
  - `( )` と `[ ]` の中の改行は空白
  - 行末が式を終われないトークンなら次の行へ続く
  - 次の行の先頭が二項演算子か `else` なら前の行へ続く
- 公式フォーマッタ `gom fmt` を持つ。出力は構文木とコメントだけで決まり、設定項目はない
- `match` の `->` などの縦揃えはしない（差分を小さくするため）

## 影響

- 長い関数適用は、パイプで分けるか括弧で囲んで折り返す（0007）
- 表層 AST はコメントと空行を trivia として保持する
- ブロック内の空行を保持するかは未決
