# List 由来の読み取り専用 View 型

- 状態: 採用
- 日付: 2026-11-18
- コンテキスト: problems/2026-11-04-shared-slice-view-type の保留分のうち、「`List`（持ち主 Gom・不変）から作る読み取り専用の部分ビュー」を足す側。wave21 prompts で「対象は List 由来のみ」が確定済み。

## 決定

新しい組み込み型 `View a`（Go 表現 `list.View[A]`、素の `[]A` の named 型）を足す。`List` は不変なので、View は MoonBit `StringView` と同じ安全性でバッキングを共有する — 部分取り出し・添字アクセスがコピーなし O(1)。

面（すべて読み取り専用）:

- `List.view : List a -> View a` — リスト全体のビュー、O(1)
- `List.slice : List a -> Int -> Int -> View a` — `xs[lo:hi]`。境界違反は Go と同じく panic
- `View.length : View a -> Int` / `View.get : View a -> Int -> Option a` / `View.slice : View a -> Int -> Int -> View a` / `View.fold : View a -> (b -> a -> b) -> b -> b` / `View.to_list : View a -> List a`（不変どうしなので共有、O(1)）
- `for x in v { ... }` の反復対象になる — 添字順、nil は 0 回

配管: `View` は `List` と同じ unqualified・shadowable な組み込み型（resolve builtin scope・check arity 1・codegen `list.View[A]`）。`View` モジュールのメンバー面と `List.view`/`List.slice` はコンパイラ登録（.gomi に書けない）— `view` を @extern 実装すると生成名 `View` が `type View[A]` と衝突するため。Go 由来の共有 View は足さない — `Go.Slice` の読み取り専用面で足りる（decision 2026-11-04-goconv-list-slice-copies）。

## 却下した案

- **`.gomi` で `fn view` を宣言**: `View a` 自体は綴れるが、実装の @extern 生成名 `View` が `type View[A]` と衝突する。メンバー名か型名のどちらかを歪めるより、コンパイラ登録（`Result.to_option` と同型）が素直。
- **`List.View` として修飾型にする**: モジュール型メンバーとしても置けるが、組み込み型 `View` の方が `List`/`Array` との対称性が取れるし、`for` 反復の shadowing 規則とも一致する。
- **View をユーザー ADT で表現**: `{s: List a, lo: Int, hi: Int}` の record は要素アクセスが添字計算込み O(1) だが境界チェックを毎回するのと、`[]A` のまま range/member 呼び出しが回る表現の方が生成コードが単純。
- **`View.to_list` をコピーにする**: 両側とも不変なので共有が安全。コピーは無駄。

## 影響

- `View` は shadowable — ファイル内 `type View` はそのファイルで組み込みを覆す（E0415 の対象になるのは `for` 反復）。
- mutable-sharing lint の扱いは変わらない — View は Gom 内だけの型で、境界を渡らない。
