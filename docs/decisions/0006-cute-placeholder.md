# 0006 Go 呼び出しの `_` プレースホルダ（`cute` 方式）

- 状態: 採用
- 日付: 2026-11-01

## 背景

`strconv.ParseInt(s, 10, 64)` のような多引数の Go 関数をパイプにつなぐには、ラムダで包む必要があった。ラムダだと `|?>` の自動ラップでステップ名が関数名にならない。

## 決定

- Go 呼び出しの引数の 1 つを `_` にすると、そこを受け取る 1 引数関数になる: `strconv.ParseInt(_, 10, 64)`
- `_` は 1 つだけ、Go 関数の呼び出しにだけ使える
- `_` 以外の引数は、関数を作る時点で 1 回だけ評価する（Scheme SRFI 26 の `cute`。`cut` や Scala のように呼び出しのたびに評価し直さない）

## 理由

- 正格評価なので、書いた位置で評価されるほうが直感に合う
- Go 呼び出しの引数には副作用があり得る。`f(_, time.Now())` を `List.map` に渡したとき、要素ごとに時刻が変わると驚く

## 影響

- `|?>` のステップ名には関数名を使える
