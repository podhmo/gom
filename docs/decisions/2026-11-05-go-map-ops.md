# `Go.Map` operations: `Go.Map.<op>` member table backed by `rt`

- 状態: 採用（実装・検証した — [検証](../sketch/2026-11-05-p3-7-interop-ops-verification.md)。spec.md §8.3/§8.5 へ反映済み）
- 日付: 2026-11-05

## Context

The P3-7 audit found `Go.Map K V` — the mapping of Go's
`map[K]V` — has no operation surface: `builtinGoMembers` lists it
as a type name only, so `Go.Map.make` is E0201 and every Go API
that takes or returns a map is unusable
([gaps ledger](../implementation-gaps.md) `Go.Map` entry).

## Decision

`Go.Map.<op>` resolves through a compiler-owned member table —
the same `rt`-backed mechanism as `Chan`/`Task`
(`internal/stdlib/builtin.go`) — reached via the *type-member*
path: `Go.Map.make` resolves `Map` as a `Go`-namespace type
member, then `make` in that type's member table. The table is
injected under the `Config.Modules` key `"Go.Map"`; without
stdlib wiring a miss reports "no member" with the same
wiring-note as a missing builtin module. `Go.Slice` gains its
read-only surface through the same hook later (`"Go.Slice"`).

Six members (`k` carries Go's `comparable` constraint, enforced
by the existing E0508 machinery — `Go.Map (List Int) Int` keys
are rejected):

| member | Gom signature | Go meaning |
| --- | --- | --- |
| `Go.Map.make` | `() -> Go.Map k v` | `make(map[K]V)` — never nil |
| `Go.Map.get` | `Go.Map k v -> k -> Option v` | `v, ok := m[k]` — nil map ok |
| `Go.Map.set` | `Go.Map k v -> k -> v -> Unit` | `m[k] = v` — nil map panics, like Go |
| `Go.Map.delete` | `Go.Map k v -> k -> Unit` | `delete(m, k)` — nil map is a no-op |
| `Go.Map.length` | `Go.Map k v -> Int` | `len(m)` — nil map is 0 |
| `Go.Map.to_list` | `Go.Map k v -> List (k, v)` | snapshot iteration — order unspecified |

- Semantics are Go's: nil maps read/delete/len fine, panic on
  set — documented rather than smoothed over.
- `to_list` is the v1 iteration surface (a `for` over maps and
  `keys`/`values` shortcuts are future work; `List.map` over the
  pairs covers most needs).
- Mutation is a property of `Go.Map` itself, not the key/value —
  matching Go: `m[k] = v` mutates the map, replacing a
  `v`'s *contents* requires the value type to be mutable.

## Alternatives

- *A Gom-side module (`.gomi` surface)*: impossible — the
  signatures are generic over `(k, v)` with a `comparable`
  constraint on `k`, which a .gomi cannot spell; and the members
  need rt-backed Go symbols anyway (the same reason `Chan`/`Task`
  are compiler-owned).
- *Bare `k, v` type parameters without `comparable`*: `MapGet`
  needs `K comparable` to compile; skipping the constraint would
  admit keys whose Go representation is a slice/map/function and
  produce generated code that fails `go build` — E0508 at the
  call site is the honest error.
- *`get` returning `(v, Bool)` or `Result`*: `Option` is the
  established comma-ok mapping (spec 8.3) and composes with
  `Option`'s existing surface.
