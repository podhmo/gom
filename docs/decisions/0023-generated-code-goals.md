# 0023 生成 Go コードの位置づけ

- 状態: 採用
- 日付: 2026-11-01

## 背景

「人間に読める Go コードを生成する」は、デバッグできる・人が保守できる・Go から使える、の 3 通りに解釈できる。

## 決定

- 目標: **デバッグ可能**（読めば何が起きたか分かる）と **Go から使える**（Go のコードから自然な API で使える）
- 非目標: 生成コードを人が直接書き換えて保守すること

## 理由

保守可能性まで求めると、ADT の表現や関数値の特殊化など、生成コードの書き方が強く縛られる。生成コードを「読める成果物」と位置づければ、表現方式と最適化の自由度が大きくなる。

## 影響

- デバッグ可能性は、名前付け、素直な制御フロー、ソース位置の対応表で満たす
- Go ABI をどこまで安定させるかは未決
