# `@test` helper とテスト関数の出力先

- 状態: 採用
- 日付: 2026-11-03

`gom test` はパッケージを 2 枚に分けて出力する: 通常の `<pkg>.go` と
テスト用の `<pkg>_test.go`（同じ package 宣言）。`test` 宣言は
`Test<Name>` 関数として `_test.go` 側に出る。

`@test` を付けたトップレベル定義は `_test.go` 側に出す（本体には出さない）。
理由:

- spec 11.5 が「テストと `@test` 定義はインターフェースに含まれない」と
  定める以上、本番の生成物に残す意味がない。同じ package の `_test.go`
  からは非公開名を含め全て参照できるので参照可能性は損なわれない
- `test` 宣言が 1 つもないパッケージでは `_test.go` 自体を出さないため、
  `@test` 定義だけが残る場合は出力を丸ごと落とす。`gom test` が実行する
  テストが無いのと同じなので問題にならない

`assert_eq` の失敗表示のために、比較対象の型ごとに `show` 関数を
コンパイラが自動生成する（core.ShowDecl → `_test.go` 側）。等価比較
コンパレータ（EqDecl）はテストが触れ得るため本体側に残す。
