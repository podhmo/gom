# LSP v1 scope: single-open-file hover + pushed diagnostics over stdio JSON-RPC

- 状態: 採用 — compile-unit 部分は [2026-11-06-lsp-package-unit](2026-11-06-lsp-package-unit.md) が Supersede する（package 単位に拡張）
- 日付: 2026-11-06
- 検証: [2026-11-06-lsp-v1-verification](../sketch/2026-11-06-lsp-v1-verification.md)

## Context

TODO P4-6 asks for the LSP foundation: type display, immediate
exhaustiveness/diagnostic reporting, and UTF-16 position conversion.
Its design inputs (docs/implementation-gaps.md, open-questions.md)
raise two position-mapping questions:

- `//line` drift aliases a reported generated line to a real but wrong
  `.gom` line; design.md 2.2 wants a SourceMap-aware inverse lookup
  with an ambiguity fallback.
- `SourceMap.SpanAt` returns whole inner-construct spans, not exact
  generated lines — is column/range precision needed for editors?

The compiler never sees output formats (design.md 2.3): diagnostics
are born `diag.Diagnostic`; LSP is one more rendering of them.

## Options

- **(i) Minimal slice**: stdio JSON-RPC + `didOpen`/`didChange`
  (full sync)/`didClose` + `hover` + `publishDiagnostics`, each open
  document compiled alone with `CheckOnly`.
- **(ii) (i) plus go-tool diagnostics**: also run `go build`/`go vet`
  on generated code and fold positions back — the slice that would
  exercise `SourceMap` and the `//line` drift question now.
- **(iii) Workspace model**: package-unit compilation with sibling
  files, didSave triggers, cancellation — closer to a real daily
  driver but a much bigger first landing.
- **(iv) Narrower still**: land only the position-mapping layer
  (UTF-16 + span inverse) and defer the protocol loop.

## Decision

Option (i). The v1 server is `internal/lsp` behind `gom lsp` on
stdio, stdlib-only (a JSON-RPC codec + LSP wire types are a few
hundred lines; an external protocol library does not earn a go.mod
dependency for this subset).

Per-document compile: `build.Compile` with `CheckOnly` — parse,
resolve, check and *pattern* all run, so hover has a typed AST and
exhaustiveness diagnostics publish immediately; lowering/codegen and
any `go` tool run stay out of the loop.

Position granularity resolved for v1: nothing in this slice needs
generated-line → `.gom` mapping at all. Diagnostics already carry
`.gom` byte spans; hover resolves against typed-AST node spans —
both byte-precise. The anchor table, the `//line` drift
hardening (SourceMap-aware reverse lookup + ambiguity fallback), and
finer column-level mapping are therefore NOT needed for v1 and stay
deferred work (open-questions keeps tracking them; they become live
again the moment the server runs the Go toolchain or serves
generated-file navigation). `diag.LineIndex` gains only
`OffsetUTF16`, the inverse of the existing `PosUTF16`, for incoming
LSP positions.

Single-open-file compile unit — the recorded limitation — **resolved
same-day by
[2026-11-06-lsp-package-unit](2026-11-06-lsp-package-unit.md), which
kept the rest of this scope unchanged**: each open document compiled
alone, so a `.gom` file that referenced names declared in sibling
files of its package saw E0201s a `gom check` of the directory would
not produce. `.gomi` documents still compile as singletons the same
way (compile stops after check; hover serves declaration heads
only).

Hover v1: innermost typed node under the cursor — `name : Type` for
`Var`/`VarPat`/`MemberExpr` selectors/pattern binders, a bare type
for other expressions, `name : Sig` for `fn` heads, `type Name` for
type heads, `module "path"` for imports. Meta types display through
the `?1`-renumbering namer, same as diagnostics.

Deferred (TODO proposals): incremental sync, `$/cancelRequest`,
`didSave`/workspace, ~~multi-file package units~~ (landed in
[2026-11-06-lsp-package-unit](2026-11-06-lsp-package-unit.md)),
go-tool diagnostic folding inside the server (needs the
SourceMap-aware inverse), completion/definition/references/code
actions, `.gomi` conformance push.

## Consequences

- New package `internal/lsp` (protocol types + JSON-RPC framing +
  server + hover lookup) and `gom lsp` CLI subcommand; cmd/gom wires
  the real compile (loader-backed `build.Options`).
- `diag` grows one conversion method (`OffsetUTF16`); the compiler
  stays protocol-blind — all LSP shapes live behind `internal/lsp`.
- Sync kind advertised is Full; hover results are `null` when the
  file has no typed AST (parse/resolve failure) or nothing covers
  the position.
- `initialize` must precede other requests (`-32002` otherwise) and
  runs once (a second `initialize` is `-32600`). After `shutdown`,
  requests answer `-32600` InvalidRequest and notifications are
  ignored; only `exit` still acts. `exit` after `shutdown` exits 0,
  without it 1. A stream EOF ends the read loop without a transport
  error, but the process still exits 1 — the spec's "0 only when
  shutdown was received" rule is applied to the whole process end.
- Panics at the message boundary never kill the process: a compile
  panic becomes an ordinary compile error surfaced as an
  "internal error" diagnostic, a request-handler panic answers
  `-32603`, and a notification-handler panic is reported via
  `window/logMessage`. A framed body is capped at 64 MiB.
- Hover markup honors the client's `contentFormat` offer
  (post-prototype refinement from the eglot check): the first
  offered kind in `markdown`/`plaintext` wins. An absent list keeps
  the server-chosen default `markdown` — the spec does not pin a
  hover default — and an offer of only unknown kinds falls back to
  `plaintext`, the one kind every client renders. Eglot offers only
  `plaintext` and gets bare text.
