# 部分適用の握り潰し — `ignore` / `_` 束縛で捨てられた関数値を警告する

- 状態: draft（wave39 lane C、調査→decision）
- 日付: 2026-11-24
- 関連: [mutable-sharing-lint](2026-11-04-mutable-sharing-lint.md)

## Context

Gom はカリー化言語なので `f x` と書くだけで残り引数を持つ関数値が
できる。文脈が関数値を期待していれば正当だが、意図せず残った
関数値が「捨てられる」形は値の握り潰しになる — wave39 prompts の
lane C はこの境界を調査し lint の要否を決める。

## 調査

実測した抜け道は「値を捨てる面」の 2 箇所だけ:

| 形 | 現状 |
| --- | --- |
| mid-block の文位置 `f x` | **E0402**（non-Unit 式は `ignore` を要求）— 既に塞がっている |
| `ignore (f x)` | 警告なし — E0402 の fix が自らこの形を案内するため、fix を適用すると即座に握り潰しが合法になる |
| `let _ = f x` | 警告なし — wildcard 束縛は型を問わず通る |
| `let g = f x`（束縛して後で適用） | 正当なカリー用法 — 区別不可 |
| `\|>` パイプ・match 腕・引数位置 | 型が要求する限り正当 — HM の型が厳密なので誤適用は型エラーになる |

他の候補（束縛後に一度も適用されない関数、公開されない補助関数）
は「関数を値として持ち回る」高階プログラミングの正常形と区別が
付かず、lint 対象としては誤検知が多すぎる。

つまり問題は「関数値を持つこと」ではなく**捨てる面に関数値が
流れ込むこと**に絞れる。検査は post-inference sweep
（`lintMutableSharing` と同じ枠）で `*Ignore` ノードの
`X.Type()` と `Let` のワイルドカード左辺の型を見るだけでよい —
`*types.Func`（Chase 後）なら警告。警告コードは新設（W 系、
PhaseLint）。`Unit -> R` の残りも `Int -> Int -> R` の残りも同じ
ルールで拾える。

## 比較した案

- **A: `ignore`・`_` 束縛の Func 値を警告（推奨）** — 検査は 2 ノード
  型判定のみ。E0402 の auto-fix が案内する形と衝突するが、それは
  「警告してもよい握り潰し」をユーザーが明示するための面であり、
  警告を消す正当な逃げ道（`ignore (f x)` したい場合は束縛して名前を
  付ける、または allow directive）は directive 機構が既に持つ
- **B: lint なし（現状維持）** — E0402 が文位置を塞いでいるので致命的
  な抜け道はないが、`ignore` 適用後は完全に沈黙する
- **C: 未適用の束縛関数を追跡する lint** — 高階関数の正常用法と区別
  不能で誤検知が支配的になるため棄却

## Decision

**A** — 捨てられた値の型（Chase 後）が `*types.Func` のとき、新しい
W コード（PhaseLint、既存の post-inference sweep に載せる）で警告する。
捨てる面は次の 3 箇所:

- `ignore e`
- `let _ = e` / `let (_, ..)` 系のワイルドカード左辺 — 関数内の
  `*Let` だけでなく、パッケージ直下の `*LetDecl` のパターンも対象
  （`walk.WalkDecl` は初期化式を訪ねるがパターンは訪ねないので、
  sweep は束縛パターンを自分で調べる）
- `match` の `_` 腕 — scrutinee の型が `*types.Func` で腕が裸の
  ワイルドカードのとき（`match (add 1) { _ -> () }` は ignore も
  let も経由せず捨てる）

比較した案の表にあった `|>`/引数位置は「捨てる」面ではなく値を
*受け渡す*面なので対象外 — Go の `any` 引数（`fmt.Println` に
`Unit -> String` を渡す）も同じ分類で、印字される関数ポインタは
open-questions の元の問いの残件として残す（値は捨てられていない、
意味を読み取れない形で消費されているだけ）。

## Consequences

- 警告なのでビルドは止まらない。確信犯は捨てずに束縛して名前を
  付ける形で沈黙させられる。`//gom:allow` は現状エラーの demote
  しかしない（`DemoteAllowed`）ので、警告の opt-out に使うには同
  directive で W コードも落とせるよう実装側で拡張する — strict
  ビルド下でも沈黙手段が必要なため
- 実装は check の lint sweep に `*Ignore`・`*Let`/`*LetDecl` の
  ワイルドカード左辺・`*Match` の `_` 腕を足すだけ — 新しい
  パイプライン面は要らない
- スコープ外: `Option.get` 経由の panic 誘導や、match の scrutinee
  を束縛する腕での部分適用は型が合っている限り触れない。`any`
  引数への関数値の引き渡し（`fmt.Println`）は捨てではないので
  警告しない — 別の問題として未決のまま残る
