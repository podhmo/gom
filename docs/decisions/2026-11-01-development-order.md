# 開発順序を P0〜P5 に変える

- 状態: 採用
- 日付: 2026-11-01

## 背景

旧計画（M0〜M4）は機能ごとに積み上げる順序で、最も重要な Go 相互運用の問題を見つけるのが遅くなる。インクリメンタルビルドも、初期に実装するには費用に見合わない。

## 決定

1. P0: Go 出力の実現可能性の検証（手書きの Go 実装案の比較。ADT、部分適用、`List`、`Result`、interface と named type）
2. P1: 最小の型付き言語（小規模な `import go` を含む）
3. P2: 型推論と関数
4. P3: Go 相互運用の本格実装
5. P4: 公開 API と開発体験（`.gomi` の検査、`gom fmt`、テスト、LSP、ビルドキャッシュ）
6. P5: 並行処理と最適化

- `.gomi` は型検査の境界として使うが、ビルドのキャッシュは P4 まで実装しない。それまでは毎回変換し、Go のビルドキャッシュに任せる

## 影響

- 最初の成功条件は「少数の ML 的な機能を使ったプログラムが、普通の Go プログラムと無理なく共存すること」
