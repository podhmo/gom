# `/` / `%` の定数ゼロ除数は型検査エラー（E0414）

- 状態: 採用
- 日付: 2026-11-02

## 決定

`/` または `%` の右辺が定数式のゼロに畳み込めるとき、その除算は型検査で
エラー（E0414）にする。判定は Go の定数式ルールに揃える:

- 整数の除算・剰余は被除数が定数でなくてもエラー（`x / 0` は Go 自身が
  「invalid operation: division by zero」で拒否する）
- `Float` は式全体が定数のときだけエラー（`10.0 / 0.0` は不可だが、
  変数を含む `x / 0.0` は IEEE の `+Inf` / `-Inf` / `NaN` として合法）

「定数式」の範囲は数値リテラル・単項の `-`・それらからなる算術式
（`+ - * / %`）・ascription の内側で、`let` 束縛の変数・関数呼び出し・
Go の定数参照は畳み込まない（Gom の `let` は Go の `const` ではなく変数に
下りるため、`let z = 0; x / z` は実行時 panic のまま残る）。

## 背景

`fn f () -> Int = 10 / 0` が check を通り `return 10 / 0` を生成していた。
Go は定数式の除算ゼロをコンパイル時に拒否するので、検査済みプログラムから
ビルド不能な Go が出ていた（canary-vet の gomgen typed seed 301 で発見）。
eval は実行時に除算ゼロで panic するため、選択肢は (a) codegen がオペランドを
非定数化して実行時 panic に揃えるか、(b) check が定数ゼロ除数を診断して
Go に揃えるかだった。(b) を採った — 検査済みプログラムが Go のコンパイルを
通ることを型検査で保証する方が codegen の回避策より素直で、`x / 0` の整数
ケースは Go 側がそもそも実行時 panic を残さない（定数式として拒否する）
ので意味のある選択肢は (b) しかなかった。

## 検証

`internal/check/check_regressions_test.go` の `TestDivZero*` で、整数の
リテラル・変数被除数・`%`・`-0` / `0x0` / `3 - 3` / `2 * 0` / `10 % 10`
の畳み込み・`Float` の全定数式と変数被除数の受理・`let` 束縛除数の受理を
確認した。ユーザー向けの振る舞いは `testdata/spec/E0414_*` と
`ok_div_float_var` / `ok_div_nonconst` が固定する。
