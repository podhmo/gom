# 0011 `.gomi` を採用し、ライブラリでは必須、`pub` は廃止

- 状態: 採用
- 日付: 2026-11-01

## 背景

実装だけを変えたときに、依存パッケージを再コンパイルせずに済ませたい（OCaml の `.mli` に相当する仕組み）。

## 決定

- パッケージの公開 API はインターフェースファイル `.gomi` に書く
- ライブラリパッケージ（`package main` 以外）は `.gomi` が必須
- 公開範囲の情報源を 1 つにするため、`pub` キーワードは廃止する
- 関数は引数リストの形で書き、arity とラベルをインターフェースに載せる
- sum type はコンストラクタまで書けば透明、名前だけなら抽象
- `gom gomi` は全トップレベル定義のシグネチャの下書きを生成する

## 影響

- 依存側は相手の `.gomi` だけを読む。再コンパイルはインターフェースのハッシュ（コメントと書式を除く）が変わったときだけ
- sum type にコンストラクタを足すと依存側が再コンパイルされ、非網羅になった `match` が見つかる
- `.gomi` は AI が API を把握するための要約としても使える
- 実装の型がインターフェースより一般的な場合を許すかは未決
